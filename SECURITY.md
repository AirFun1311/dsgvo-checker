# Security Policy

## 🔒 Supported Versions

We provide proactive security updates and vulnerability patches for the following versions:

| Version | Supported          | Security Maintenance Level |
| ------- | ------------------ | -------------------------- |
| 2.0.x   | :white_check_mark: | Active Development & SLA   |
| < 2.0   | :x:                | End of Life (EOL)          |

---

## 🛡️ Reporting a Vulnerability

We prioritize the security of our compliance scanner, data integrity, and responsible disclosure. If you discover a security vulnerability or sensitive data exposure issue, please follow our coordinated disclosure policy.

### Submission Process

1. **Do NOT open a public GitHub issue** for undisclosed security vulnerabilities.
2. Email your findings directly to the maintainer: **`sf.foodzeit@googlemail.com`**
3. Include the following details to assist rapid triage:
   - Severity assessment (CVSS v3.1 vector if applicable)
   - Step-by-step reproduction guide or proof-of-concept (PoC)
   - Affected scanner module, header evaluator, or dependency
   - Potential impact on client website telemetry

---

## ⏱️ Response & Triage SLA

* **Initial Response**: Within **24 hours**
* **Vulnerability Assessment & Triage**: Within **48 hours**
* **Security Patch Release & Advisory**: Within **7 business days** (depending on CVSS score)

## 🏛️ Standards & Multi-Jurisdictional Baseline

Our security practices align with:
* **EU**: NIS2 Directive (Directive EU 2022/2555), ISO/IEC 27001:2022, DSGVO Art. 32 TOMs
* **USA**: NIST SP 800-53 Rev. 5, Executive Order 14028 (Software Supply Chain Integrity)
* **OpenSSF**: Open Source Security Foundation Best Practices & SLSA Framework
